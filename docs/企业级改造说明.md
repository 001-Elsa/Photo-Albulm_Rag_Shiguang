# 工程化实验说明

当前定位仍是**可演进的单机多模态检索系统**，不是已经完成的企业媒资平台。
本文只记录已经落地的工程基线与尚未完成的企业化边界。

## 一、本次改造内容

### 1. 存储抽象层(`vectorstore.py`)
- `LocalVectorStore`:内存矩阵,单机 10 万级(默认)
- `PgVectorStore`:PostgreSQL + pgvector、HNSW 索引的实验性适配；尚未完成大规模容量与并发验证
- 接口三个方法(`refresh/search/stats`),换 Milvus 只需再实现一个类
- 配置切换:`vector_backend: local | pgvector`;pgvector 连不上自动降级 local 并告警

### 2. schema 版本迁移(`migrations.py`)
- `schema_version` 落库,启动自动补齐落后版本,幂等可重入
- v0.8/v0.9 老库无损升级(实测:老数据 + 新表并存)
- 规矩:新变更只能追加,禁止修改历史迁移

### 3. 认证与 RBAC(`auth.py`)
- 口令:Argon2id；兼容旧 PBKDF2 哈希
- 会话:HMAC-SHA256 签名短期令牌,HttpOnly + SameSite=Strict Cookie / Bearer 双通道
- 角色:`admin`(索引、设置、用户管理、审计)/ `viewer`(搜索、浏览)
- 角色/禁用状态每次请求从数据库读取，变更立即生效
- 企业模式通过环境变量注入会话密钥和初始管理员密码，不生成明文密码文件
- 公开注册和指标端点默认关闭
- 用户管理 API:`POST /api/users`、`POST /api/password`、`GET /api/users`

### 4. 审计日志
- 登录(含失败)、搜索、原图查看、索引、设置变更全部落 `audit_log` 表
- `GET /api/audit`(admin)查看;这是企业合规的最低要求

### 5. 可观测性(`observability.py`)
- `GET /livez`:进程存活
- `GET /readyz` / `GET /healthz`:schema 版本、模型和向量索引状态
- `GET /metrics`:Prometheus 文本格式——请求计数(路径归一化防高基数)、
  搜索延迟直方图、索引量 gauge
- 结构化 JSON 日志(`json_logs: true`),接 ELK/Loki 即用

### 6. 限流
- 令牌桶(按用户):默认突发 30、稳态 2 req/s,超限 429;参数可配

### 7. 12-factor 配置
- 所有配置项支持环境变量覆盖:`SHIGUANG_<字段大写>`(容器部署标准姿势)

### 8. 容器化与 CI
- `Dockerfile`(healthcheck 内置)、`docker-compose.yml`(可选 pgvector profile)
- GitHub Actions:3 个 Python 版本矩阵跑测试 + 编译检查 + Docker 构建

## 三、你机器上的联调清单

```bash
# 1. 个人模式(SQLite + 内存向量，默认只监听本机)
python run.py

# 2. Docker Compose（API + pgvector）
docker compose up -d --build

# 3. 本机进程连接 pgvector
SHIGUANG_VECTOR_BACKEND=pgvector SHIGUANG_PG_DSN=postgresql://shiguang:<password>@localhost:5432/shiguang python run.py

# 4. 健康检查
curl http://127.0.0.1:8626/healthz
```

## 四、简历写法(这一阶段新增的话术)

> - 设计可插拔向量存储层(内存矩阵/实验性 pgvector-HNSW)，支持配置切换和故障降级；具体容量以真实压测为准
> - 实现 Argon2id+签名令牌认证、RBAC、审计日志、令牌桶限流、Prometheus 指标、结构化日志、schema 版本迁移和 Docker/CI 工程基线
> - 实现带指数退避、心跳回收、取消/人工重试及事务幂等写入的 SQLite 持久化索引任务状态机
