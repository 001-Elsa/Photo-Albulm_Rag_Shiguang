# v0.9.0 升级说明(2026-07-26)

## 一、修复的问题(代码审查发现)

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | **UPSERT 更新路径返回错误 id**:文件被修改后重新入库时,`upsert_photo` 走 `ON CONFLICT DO UPDATE` 分支,SQLite 的 `lastrowid` 返回的是上一次 INSERT 的 id,导致把**别的照片**标为 ready | 正确性 bug,已用测试复现 | 改为按 path 回查 id;新增回归测试 `test_upsert_returns_stable_id` |
| 2 | 三个索引阶段统计总数时 `SELECT *` 捞全表 | 10 万张图时白耗几百 MB 内存 | 新增 `count_pending()` 用 `COUNT(*)` |
| 3 | 文件监听收到编辑器重复触发的 modified 事件时,未变化的文件也会整套重做(重嵌入/重OCR) | 白耗算力 | 增量消费前先查 size+mtime 未变则跳过 |
| 4 | ONNX 动态导出时输出 shape 是符号名,`dim` 可能不是整数 | 换 ONNX 后端时向量维度记录错误 | 非整数时实测一次文本编码取真实维度 |
| 5 | UPSERT 的 UPDATE 分支漏了 `place` 字段 | 地点信息更新丢失 | 补上 `place=excluded.place` |

## 二、新功能

### 1. 以图搜图(点开任意照片 → "找相似照片")
复用已入库的 CLIP 图片向量,`GET /api/similar/{id}`,不需要额外索引成本。
找同一场景的连拍、找"这张图的原图/表情包出处"都好用。

### 2. 离线逆地理:"在杭州拍的"可以搜了
- 内置约 90 个城市质心坐标(`geo.py`),GPS → 城市名,零网络请求
- 扫描时自动写入 `place`;老库有 GPS 没地点的照片,下次索引自动回填
- 查询解析识别城市名:"在杭州拍的西湖" → `{place:杭州, semantic:西湖}`
- **软过滤**设计:库里没有该城市的照片时不硬过滤,地点词退回语义通道,避免搜不到

### 3. 时间表达增强
- 季节:"冬天的雪" → 12/1/2 月(跨年正确处理),季节词同时保留在语义通道
- 相对月份:"上个月""这个月"(1 月说"上个月"会正确回到去年 12 月)
- 月份从单值改为集合(`months`),为后续"上半年""国庆假期"留好扩展位

测试从 17 个增加到 26 个,全部通过;端到端冒烟(扫描→回填地点→地点搜索→以图搜图)通过。

## 三、后续升级路线(按性价比排序)

1. **检索质量**(先做,直接改简历数字):跑真实相册评估 → 调 RRF 权重 → 换 large 模型对比
2. **行政区划精确化**:城市质心 → 离线省市区边界(GeoJSON 点包含判断),支持"在西湖区拍的"
3. **时间线视图**:按月聚合的时间轴浏览 + "这一天"回忆
4. **视频支持**:抽关键帧进同一套索引,搜"去年演唱会的视频"
5. **CLIP 微调**(W7 进阶):用自己相册的 OCR/地点做弱监督对,LoRA 微调 domain 适配
6. **多端**:Tauri 打包桌面安装包;局域网手机访问(需加访问令牌)
