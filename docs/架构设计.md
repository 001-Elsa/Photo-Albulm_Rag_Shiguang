# 架构设计

## 总览

```
┌─ Web UI(shiguang/web/index.html,原生 JS,单文件)
│    检索 / 人物 / 去重 / 设置+进度(SSE)
├─ FastAPI(shiguang/api.py)
│    /api/search /api/index/* /api/persons /api/dupes /api/settings
├─ 查询解析(query_parser.py)
│    规则引擎(默认) │ Ollama 本地小模型(可选,失败回落规则)
├─ 检索引擎(search.py)
│    VectorIndex 内存矩阵(语义) + SQLite FTS5(OCR 文字) + SQL 过滤(EXIF/人物/截图)
│    → RRF(Reciprocal Rank Fusion)融合
├─ 索引管线(indexer.py)
│    scan → embed → ocr → faces → cluster,index_jobs 持久化状态机
│    watchdog 增量监听(防抖 3s 批处理)
├─ 模型层(embedder.py / ocr.py / faces.py)
│    Chinese-CLIP(onnx int8 > transformers > demo 桩,自动降级)
│    RapidOCR │ InsightFace(均可选,不装则该通道自动关闭)
└─ 存储(db.py)
     SQLite 单文件:photos / embeddings(BLOB) / ocr_text+FTS5 / faces / persons
     缩略图:data/thumbs/<sha1前2位>/<sha1>.jpg
```

## 关键设计决策(面试要点)

### 1. 向量检索为什么不用 FAISS/Milvus?

个人相册量级(1万~10万张)、512 维 float32,全量矩阵 = 10万 × 512 × 4B ≈ 200MB,
numpy 暴力点积 <10ms——**引入向量数据库属于过度设计**。矩阵常驻内存、
photo_id 对齐,增量后 `refresh()` 重载。量级到百万再换 FAISS-IVF,接口已隔离在
`VectorIndex`,替换成本一个类。

### 2. 三路混合检索怎么融合?

- 语义通道:CLIP 文本向量 × 图片矩阵,取 top-N 排名
- 文字通道:FTS5 `bm25()` 排名(截图/文档强通道)
- 结构化条件(年/月/人物/截图)不参与打分,做**硬过滤**(白名单集合)
- 排名融合用 **RRF**:`score = Σ w_i/(k+rank_i)`,免调分数尺度,两通道皆命中自然置顶。
  权重 `weight_semantic/weight_ocr` 可配,评估脚本可量化调参收益。

### 3. 断点续建怎么做?

调度只依据 `index_jobs`，状态为
`pending/running/retrying/succeeded/failed/cancelled/skipped`。Worker 原子领取任务，
失败按指数退避进入 `retrying`，达到上限才进入 `failed`；`heartbeat_at` 过期后可回收。
结果 upsert 与任务成功状态在同一短事务中提交，并校验照片内容哈希仍与任务一致。
`photos.embedded/ocr_done/faces_done` 只保留兼容统计，不再控制任务领取。

### 4. 模型不可用时怎么降级?

embedder 按 `onnx → transformers → demo` 自动降级;OCR/人脸没装则该通道
关闭、对应任务记为 `skipped`，**功能缺失不冒充处理成功**。demo 桩输出确定性伪向量,
保证零依赖环境可跑通全链路(也是单测的基础),UI 明确黄色警告防误用。

### 5. 人脸聚类为什么不用 DBSCAN?

自实现贪心中心聚类(O(n·k)、免 sklearn、结果稳定可复现),阈值 0.55 对
buffalo_l 特征经验可用。全量重聚类幂等,已命名人物按"最大脸集合重叠"迁移名字,
改名不丢。

### 6. 截图判定

文件名关键词 + (PNG ∧ 无相机EXIF ∧ 接近常见屏幕比例) 启发式,零成本、可解释;
误判率通过评估集量化,未来可换轻量分类器。

### 7. 隐私边界

默认启动不联网下载模型（首次下载需显式开启）;所有产物(库、缩略图、向量)在
`data/`,单目录可删可迁移。

## 数据流(一次搜索)

```
"去年在海边拍的日落"
  → parse:  {semantic:"海边 日落", keywords:[海边,日落], year:2025}
  → filter: year=2025 的 photo_id 白名单
  → 语义:   encode_text → 矩阵点积 top-180 ∩ 白名单
  → 文字:   FTS5 "海边" OR "日落" ∩ 白名单
  → RRF 融合 → top-60 → 补齐缩略图/时间/命中原因 → 前端网格
```
