# 评估指南(W5,简历核心素材)

## 为什么这一步不能省

"我做了个搜图工具"是描述;"自建 100 条查询测试集,Recall@5 从 58% 优化到 86%,
P95 延迟 120ms"是证据。评估体系让每次改动可度量、可回滚、可写进简历。

## 步骤

### 1. 建测试集(约 1~2 小时)

```bash
python eval/build_testset.py --sample 30   # 随机抽 30 张照片帮你出题
```

编辑 `eval/testset.csv`,建议 100 条,按三类配比:

| 类型 | 条数 | 例子 | 考察通道 |
|---|---|---|---|
| 纯语义 | ~50 | 海边日落 / 火锅聚餐 / 雪山 | CLIP 向量 |
| 文字类 | ~25 | 高铁票截图 / 微信账单 | OCR+FTS5 |
| 条件复合 | ~25 | 去年的樱花 / 和妈妈的合影 | 解析+过滤+融合 |

标注技巧:先随便搜,把"应该搜到的那张"的完整路径贴进 expected_paths(分号分隔多张)。

### 2. 跑基线并存档

```bash
python eval/run_eval.py --tag baseline
```

### 3. 优化循环(每改一处,评一次,存一档)

可调的旋钮(按性价比排序):

1. `weight_ocr` / `weight_semantic` / `rrf_k`(data/config.json,零成本)
2. 查询解析:看"未命中查询"列表里解析错了什么,补规则或换 ollama 模式
3. 换 embedding 模型:`chinese-clip-vit-base-patch16` → `large-patch14`(慢但准)
4. OCR 开关与截图判定阈值

```bash
python eval/run_eval.py --tag v2
python eval/run_eval.py --compare baseline v2   # Δ 一目了然
```

### 4. 性能基准(W7 配套)

```bash
python scripts/benchmark.py --backend transformers --tag fp32
python scripts/export_onnx.py --int8
python scripts/benchmark.py --backend onnx --tag int8
python scripts/benchmark.py --compare fp32 int8
```

得到:索引吞吐(张/秒)、文本编码延迟 P50/P95、峰值内存——量化前后各一份。

## 指标口径(面试会问)

- **Recall@K**:前 K 个结果中出现任一正确答案的查询占比(单答案集合命中口径)
- **MRR**:第一个正确答案名次的倒数取平均,未命中记 0——衡量"排得多靠前"
- **延迟**:解析+检索+组装端到端,不含首次模型加载;报 P50/P95 而非平均
- 局限性(主动说更加分):测试集自标注有偏、单人标注无一致性校验、
  答案集合可能不完备(库里还有别的日落)→ 所以同时看 MRR 与 misses 列表人工复核
